# Sysmon Process and Network Monitoring Investigation

## Objective

Configure Sysmon on a Windows 11 workstation to collect process creation and network connection telemetry, then examine the events in Event Viewer and compare process monitoring with native Windows Security auditing.

## Lab Environment

- **Workstation:** Windows 11 (`WS01`)
- **Monitoring tool:** Microsoft Sysmon
- **Log location:** Applications and Services Logs → Microsoft → Windows → Sysmon → Operational
- **Configuration:** Custom XML configuration, schema version 4.91

## Investigation 1: Process Creation

**Event ID:** 1 — Process Create

**Activity:** Opened Notepad on the lab workstation.

**Evidence:** `../screenshots/sysmon-event-1-process-creation.png`

### Observations

The Sysmon event recorded the Notepad process and exposed process details, including the executable path, command line, and parent process information.

### Analysis

Process creation telemetry helps analysts investigate which executables run, how they are launched, and how processes relate to one another. These details can help identify suspicious execution patterns when combined with other evidence.

## Investigation 2: Network Connection

**Event ID:** 3 — Network connection

**Activity:** Tested connectivity to `example.com` over TCP port 443 using `Test-NetConnection`.

**Evidence:** `../screenshots/sysmon-event-3-network-connection.png`

### Observations

After enabling network connection logging through a custom Sysmon XML configuration, Event ID 3 entries appeared in the Sysmon Operational log. One observed event included destination port 443, an associated `svchost.exe` process, and `Initiated: true`.

### Analysis

Event ID 3 can provide process and endpoint context for network connections. The observed event confirms that Sysmon recorded a connection on port 443; however, the available evidence alone does not establish that this specific event was generated by the connectivity test or that the activity was malicious.

## Investigation 3: Native Windows Process Auditing

**Event ID:** 4688 — A new process has been created

**Activity:** Located a Security log entry showing Notepad in the New Process Name field.

**Evidence:** `../screenshots/windows-security-event-4688-notepad.png`

### Observations

Windows Security auditing recorded the creation of the Notepad process.

### Analysis

Sysmon Event ID 1 and Windows Security Event ID 4688 can provide complementary process-creation evidence. Comparing the two sources helps analysts understand process execution from multiple logging perspectives.

## Key Findings

- Verified Sysmon process creation monitoring with Event ID 1.
- Enabled Sysmon network connection logging through a custom XML configuration.
- Verified network connection telemetry with Event ID 3.
- Located native Windows Security Event ID 4688 for Notepad.
- Practiced evidence-based analysis without assuming that an event is malicious solely because it exists.

## Limitations

This was a controlled, single-workstation lab. It did not include a production SIEM, centralized log collection, automated alerting, or a confirmed malicious activity investigation. Findings are limited to the events observed during the exercises.
